# 배깅과 랜덤 포레스트: 부트스트랩, OOB, 특성 무작위성

## 오늘의 질문

- 왜 결정 트리 한 그루보다 여러 트리의 평균이 안정적일까?
- 부트스트랩(Bootstrap)과 배깅(Bagging)은 어떻게 다를까?
- 원본 데이터가 $n$개인데 부트스트랩 표본에는 왜 약 $0.632n$개의 고유한 행만 들어갈까?
- OOB(Out-of-Bag) 예측은 어떻게 만들며, 별도의 Validation을 완전히 대체할 수 있을까?
- 랜덤 포레스트(Random Forest)가 사용하는 두 종류의 무작위성은 무엇일까?
- `max_features`가 너무 작거나 트리 수를 계속 늘리면 어떤 일이 생길까?
- MDI와 순열 중요도(Permutation Importance)는 각각 어떤 질문에 답할까?

## 핵심 결론

결정 트리 한 그루는 데이터가 조금만 바뀌어도 구조가 크게 달라질 수 있는 높은 분산(high variance)을 가진다. 배깅은 서로 다른 부트스트랩 표본으로 여러 모델을 학습한 뒤 예측을 모아 이 흔들림을 줄인다.

랜덤 포레스트는 여기에 각 노드에서 사용할 특성 후보도 무작위로 제한한다. 중요한 것은 트리 수나 무작위성 자체가 아니라 다음 두 조건의 균형이다.

```text
개별 트리의 충분한 예측력
            +
트리 사이의 낮은 오류 상관
            ↓
안정적인 앙상블 예측
```

## 전체 흐름

```text
불안정한 결정 트리
        ↓
행을 복원 추출한 부트스트랩 표본
        ↓
여러 트리를 학습하고 예측을 집계하는 배깅
        ↓
각 노드의 특성 후보까지 무작위로 제한
        ↓
랜덤 포레스트
```

용어를 먼저 짧게 구분하면 다음과 같다.

1. **부트스트랩은** 원본 데이터에서 복원 추출하여 표본을 만드는 방법이다.
2. **배깅은** 여러 부트스트랩 표본에 모델을 학습하고 예측을 집계하는 앙상블 전략이다.
3. **랜덤 포레스트는** 결정 트리 배깅에 노드별 무작위 특성 선택을 추가한 모델이다.
4. **OOB 표본은** 특정 트리의 부트스트랩 표본에 한 번도 뽑히지 않은 행이다.

## 왜 결정 트리를 여러 개 만들까?

### 결정 트리 한 그루는 불안정하다

검색 문서의 관련성을 판단하는 결정 트리가 다음 조건으로 시작한다고 하자.

```text
retrieval_score > 0.8?
├── Yes → recency > 0.5?
│          ├── Yes → Relevant
│          └── No  → Irrelevant
└── No  → Irrelevant
```

학습 데이터의 일부만 바뀌어도 첫 번째 분할이 다음처럼 달라질 수 있다.

```text
document_length > 1200?
```

루트 분할이 바뀌면 그 아래의 가지 구조도 연쇄적으로 달라질 수 있다. 깊은 결정 트리는 복잡한 관계를 잘 표현하지만, 학습 데이터의 작은 변화에 모델 구조와 예측이 크게 흔들리는 높은 분산을 가질 수 있다.

### 여러 예측의 평균으로 흔들림을 줄인다

전문가 세 명의 예측 확률이 다음과 같다고 하자.

```text
전문가 1 → 0.70
전문가 2 → 0.55
전문가 3 → 0.80
평균     → 0.6833
```

한 명의 예측이 우연히 높거나 낮아도 여러 예측을 평균하면 개별적인 흔들림을 일부 상쇄할 수 있다. 이것이 앙상블(ensemble)의 기본 아이디어다.

하지만 완전히 같은 모델을 복제하는 것만으로는 효과가 없다.

```text
Tree 1   → 0.80
Tree 2   → 0.80
Tree 3   → 0.80
...
Tree 100 → 0.80
평균     → 0.80
```

동일한 예측을 몇 번 평균해도 결과는 달라지지 않는다. 따라서 여러 트리가 어느 정도 정확하면서도 서로 다른 방식으로 실수하도록 만들어야 한다.

## 부트스트랩과 배깅

### 부트스트랩은 복원 추출이다

원본 데이터가 다음과 같다고 하자.

```text
[A, B, C, D, E]
```

이 데이터에서 뽑은 행을 다시 넣으면서 5번 추출하면 다음과 같은 부트스트랩 표본을 만들 수 있다.

```text
Tree 1: [A, A, C, D, E]
Tree 2: [B, B, C, C, E]
Tree 3: [A, B, D, D, E]
```

첫 번째 표본에서는 A가 두 번, B가 0번 등장한다. 새로운 의미를 가진 행을 생성한 것이 아니라 기존 행이 학습에 기여하는 횟수가 달라진 것이다. 따라서 이 문맥의 부트스트랩은 새로운 데이터를 합성하는 데이터 증강(data augmentation)과 구분해야 한다.

### 배깅은 전체 앙상블 전략이다

Bagging이라는 이름은 Bootstrap Aggregating에서 왔다.

```text
                         ┌─ Bootstrap 1 → Model 1 ─┐
Training Dataset ────────┼─ Bootstrap 2 → Model 2 ─┼─→ 평균 또는 투표
                         └─ Bootstrap 3 → Model 3 ─┘
```

- Bootstrap: 각 모델에 전달할 학습 표본을 만드는 방법
- Aggregating: 여러 모델의 예측을 평균하거나 투표로 모으는 과정
- Bagging: 이 두 과정을 합친 앙상블 전략

배깅의 기반 모델이 반드시 결정 트리일 필요는 없지만, 높은 분산을 가진 깊은 결정 트리와 특히 잘 맞는다.

### 고유한 행은 왜 약 63.2%일까?

원본 데이터에 행이 $n$개 있고, 그중 특정 행 A를 생각하자. 한 번 추출할 때 A가 뽑히지 않을 확률은 다음과 같다.

$$
1-\frac{1}{n}
$$

원본과 같은 크기의 부트스트랩 표본을 만들기 위해 복원 추출을 $n$번 하면, A가 한 번도 뽑히지 않을 확률은 다음과 같다.

$$
\left(1-\frac{1}{n}\right)^n
$$

$n$이 커질 때 이 값은 다음 극한에 가까워진다.

$$
\lim_{n\to\infty}
\left(1-\frac{1}{n}\right)^n
=e^{-1}
\approx 0.368
$$

따라서 A가 최소 한 번 뽑힐 확률은 다음과 같다.

$$
1-e^{-1}\approx 0.632
$$

여기서 $63.2\%$는 부트스트랩 표본의 전체 길이가 원본과 같은 $n$일 때의 **고유한 행 비율의 기댓값에 대한 근사치다**. 표본의 길이는 $n$이지만 중복이 있으므로 고유한 원본 행은 약 $0.632n$개이고, 빠진 행은 약 $0.368n$개다.

## OOB 예측과 평가

### OOB는 트리마다 달라진다

첫 번째 트리의 부트스트랩 표본이 다음과 같다고 하자.

```text
원본:  [A, B, C, D, E]
Tree 1 학습 표본: [A, A, C, D, E]
```

Tree 1은 B를 한 번도 보지 않았으므로 B는 Tree 1에 대해 OOB다. 그러나 다른 트리가 B를 학습에 사용했다면 B는 그 트리에 대해서는 OOB가 아니다.

```text
부정확한 표현: B는 OOB다.
정확한 표현:   B는 Tree 1에 대해 OOB다.
```

OOB 여부는 행에 고정된 속성이 아니라 **행과 트리의 관계다**.

### 한 행의 OOB 예측을 만드는 방법

트리가 300개이고 행 B의 포함 여부가 다음과 같다고 하자.

```text
Tree 1 → OOB
Tree 2 → 학습에 사용
Tree 3 → OOB
Tree 4 → 학습에 사용
...
```

B의 OOB 예측에는 B를 학습하지 않은 트리만 사용한다.

```text
Tree 1의 양성 확률 → 0.60
Tree 3의 양성 확률 → 0.72
Tree 7의 양성 확률 → 0.65
...
```

행 $i$를 학습하지 않은 트리의 집합을 $\mathcal{T}_i$라고 하면, 이진 분류의 OOB 양성 확률은 다음처럼 나타낼 수 있다.

$$
\hat{p}_{\mathrm{OOB}}(\mathbf{x}_i)
=
\frac{1}{\lvert\mathcal{T}_i\rvert}
\sum_{t\in\mathcal{T}_i}
\hat{p}_t(y=1\mid\mathbf{x}_i)
$$

행 하나가 트리 하나에 대해 OOB일 확률은 약 $0.368$이므로, 트리가 300개라면 한 행은 평균적으로 다음 개수의 트리에서 OOB 예측을 받는다.

$$
300\times 0.368\approx 110
$$

### OOB 점수는 공짜 Validation과 비슷하다

각 학습 행에 대해 그 행을 보지 않은 트리들의 예측을 모으면 학습 데이터 전체의 OOB 예측을 만들 수 있다. 별도의 Holdout을 떼지 않고도 일반화 성능을 추정할 수 있다는 점에서 OOB 평가는 흔히 “공짜 Validation”에 비유된다.

scikit-learn의 `RandomForestClassifier`에서 `oob_score=True`로 학습하면 `oob_score_`에 기본적으로 OOB 예측의 Accuracy가 기록된다. 클래스가 불균형하면 Accuracy만으로 판단하지 말고 `oob_decision_function_`의 OOB 확률로 Average Precision(AP) 같은 문제에 맞는 지표도 계산해야 한다.

예를 들어 관련 문서가 5%, 비관련 문서가 95%인 데이터에서 모든 문서를 비관련으로 예측해도 Accuracy는 95%다. 이 모델은 관련 문서를 하나도 찾지 못하므로 높은 Accuracy만으로 유용하다고 판단할 수 없다.

### OOB가 Validation을 완전히 대체하지는 않는다

하나의 원문을 여러 청크로 나눈 데이터를 생각하자.

```text
Document A
├── Chunk A1
├── Chunk A2
├── Chunk A3
└── Chunk A4
```

어떤 트리가 A1은 학습하고 A2는 OOB로 남겼다면, A2를 직접 보지는 않았어도 거의 같은 원문에서 나온 정보를 이미 학습했을 수 있다. 이 경우 OOB 성능이 실제 배포 성능보다 낙관적으로 측정될 수 있다.

다음과 같은 의존성이 있으면 목적에 맞는 별도 분할을 검토해야 한다.

- 같은 문서에서 나온 여러 청크
- 같은 사용자가 만든 여러 행
- 같은 시점이나 세션에서 수집한 여러 행
- 미래 데이터로 일반화해야 하는 시계열 데이터

예를 들어 실제 배포 환경에서 새로운 문서에 대한 성능이 중요하다면 행 단위 무작위 분할 대신 문서 단위 Group Split이 필요할 수 있다.

## 랜덤 포레스트가 추가하는 특성 무작위성

### 배깅만으로는 트리들이 비슷해질 수 있다

RAG 관련성 분류기에 다음 특성이 있다고 하자.

```text
x₁ = retrieval_score
x₂ = document_length
x₃ = source_type
x₄ = recency
x₅ = query_length
```

`retrieval_score`가 매우 강력하면 모든 특성을 항상 볼 수 있는 여러 트리가 루트에서 비슷한 분할을 선택할 수 있다.

```text
Tree 1 → retrieval_score > 0.81
Tree 2 → retrieval_score > 0.79
Tree 3 → retrieval_score > 0.82
```

부트스트랩 표본이 달라도 트리 구조와 오류가 비슷해지면 예측을 평균하는 효과가 줄어든다.

### 각 노드에서 특성 후보를 다시 뽑는다

랜덤 포레스트는 분할을 찾을 때 전체 특성 중 일부를 무작위 후보로 선택하고, 그 후보 안에서 가장 좋은 분할을 찾는다.

```text
전체 특성: [x₁, x₂, x₃, x₄, x₅]

루트 노드 후보:     [x₂, x₅]
왼쪽 자식 노드 후보: [x₁, x₄]
오른쪽 자식 노드 후보: [x₃, x₅]
```

특성 집합을 트리마다 한 번만 정하는 것이 아니라 **분할할 노드마다 다시 후보를 뽑는다**. 또한 후보 중 특성을 아무렇게나 고르는 것이 아니라 불순도를 가장 많이 줄이는 분할을 찾는다.

```text
특성 후보군을 무작위로 선택
             ↓
후보 안에서 가장 좋은 분할을 탐색
```

### `max_features`의 역할

```python
from sklearn.ensemble import RandomForestClassifier

RandomForestClassifier(max_features="sqrt")
```

특성이 100개라면 각 분할에서 대략 $\sqrt{100}=10$개의 특성을 후보로 사용한다. 강한 특성이 어떤 노드의 후보에서 제외되면 다른 특성이 선택될 기회가 생기므로 트리 사이의 상관을 낮출 수 있다.

`max_features`를 줄일수록 다양성이 반드시 좋아진다고 단정할 수는 없다. 일반적으로 다음과 같은 상충 관계가 생긴다.

```text
max_features 감소
→ 트리 사이 상관 감소 가능성: 유리
→ 각 노드의 좋은 분할을 놓칠 가능성: 불리

max_features 증가
→ 각 트리의 예측력 증가 가능성: 유리
→ 트리들이 비슷해질 가능성: 불리
```

`max_features=1`이면 후보 특성이 하나뿐이므로 트리의 다양성은 커질 수 있지만, 중요하지 않은 특성이 뽑힌 노드에서는 나쁜 분할을 선택하거나 분할하지 못할 수 있다. 좋은 랜덤 포레스트는 개별 트리의 예측력과 트리 사이의 낮은 상관을 함께 유지해야 한다.

## 평균이 분산을 줄이는 원리

### 독립인 경우부터 생각한다

트리 $N$개의 예측을 $T_1,T_2,\ldots,T_N$이라고 하면 평균 예측은 다음과 같다.

$$
\overline{T}
=
\frac{1}{N}
\sum_{i=1}^{N}T_i
$$

각 트리 예측의 분산이 모두 $\sigma^2$이고 서로 독립이라면 평균 예측의 분산은 다음과 같다.

$$
\mathrm{Var}(\overline{T})
=
\frac{\sigma^2}{N}
$$

트리가 100개이면 개별 트리 분산의 $1/100$까지 줄어든다.

### 실제 트리는 서로 독립이 아니다

랜덤 포레스트의 트리들은 같은 원본 데이터와 특성을 공유하므로 어느 정도 비슷한 실수를 한다. 모든 트리의 분산이 $\sigma^2$이고 서로 다른 두 트리 사이의 상관계수가 모두 $\rho$라고 단순화하면 다음 식을 얻는다.

$$
\begin{aligned}
\mathrm{Var}(\overline{T})
&=
\frac{1}{N^2}
\left[
N\sigma^2+N(N-1)\rho\sigma^2
\right] \\
&=
\sigma^2
\left[
\rho+\frac{1-\rho}{N}
\right]
\end{aligned}
$$

두 항으로 나누어 읽으면 의미가 더 분명하다.

$$
\underbrace{\rho\sigma^2}_{\text{트리들이 함께 흔들리는 부분}}
+
\underbrace{\frac{(1-\rho)\sigma^2}{N}}_{\text{트리별 독립적인 흔들림}}
$$

두 번째 항은 트리 수 $N$을 늘리면 작아지지만, 첫 번째 항은 사라지지 않는다.

### 숫자로 확인하기

$\sigma^2=1$이라고 하자.

- $\rho=0$, $N=100$이면 분산은 $0.01$이다.
- $\rho=0.2$, $N=100$이면 분산은 $0.2+0.8/100=0.208$이다.
- $\rho=0.2$, $N=10{,}000$이어도 분산은 $0.2+0.8/10{,}000=0.20008$이다.

따라서 $N$이 무한히 커져도 단순화한 식의 극한은 다음과 같다.

$$
\lim_{N\to\infty}
\mathrm{Var}(\overline{T})
=\rho\sigma^2
$$

이 식은 `n_estimators`를 처음 늘릴 때는 성능이 좋아질 수 있지만, 어느 지점부터 개선 폭이 작아지는 이유를 보여 준다. 트리 수를 계속 늘리는 것만으로 트리들이 함께 틀리는 문제를 해결할 수는 없다.

### Bias-Variance 관점

깊은 결정 트리는 복잡한 패턴을 표현해 Bias를 낮출 수 있지만 데이터 변화에 민감해 Variance가 높아질 수 있다. 배깅은 이런 트리 여러 개의 예측을 평균하여 주로 Variance를 줄인다. 랜덤 포레스트는 특성 무작위성까지 추가해 트리 사이의 상관도 낮추려 한다.

```text
깊은 결정 트리
→ 낮은 Bias, 높은 Variance
→ 부트스트랩과 배깅
→ Variance 감소
→ 노드별 특성 무작위성
→ 트리 사이 상관 감소 유도
```

## 특성 중요도 해석

### MDI는 학습 중 불순도를 얼마나 줄였는가를 본다

`forest.feature_importances_`는 각 특성이 트리의 분할에서 감소시킨 불순도를 누적하고 정규화한 값이다. 보통 불순도 기반 특성 중요도 또는 MDI(Mean Decrease in Impurity)라고 부른다.

```text
부모 노드: 양성 50, 음성 50
              ↓ retrieval_score로 분할
왼쪽 노드: 양성 5,  음성 45
오른쪽 노드: 양성 45, 음성 5
```

이 분할은 자식 노드의 클래스를 더 순수하게 만들므로 불순도를 크게 줄인다. 어떤 특성이 이런 분할에 자주 사용되면 MDI가 커진다.

다만 `user_id`, `document_id`, `request_id`처럼 값의 종류가 많은 특성은 분할 후보가 많아 우연히 학습 데이터의 불순도를 크게 낮추기 쉽다. 따라서 높은 MDI만 보고 현실에서 중요한 특성이나 인과적 원인이라고 결론 내리면 안 된다.

### 순열 중요도는 특성 정보를 망가뜨렸을 때의 성능 하락을 본다

학습을 마친 모델과 Validation 데이터가 있다고 하자. `retrieval_score` 열 하나만 무작위로 섞으면 행의 레이블과 이 특성의 관계가 깨진다.

```text
원래: [0.81, 0.32, 0.75, 0.64]
순열: [0.32, 0.75, 0.64, 0.81]

원래 AP = 0.82
순열 AP = 0.65
중요도 = 0.82 - 0.65 = 0.17
```

즉 순열 중요도는 “이 모델이 이 데이터에서 예측할 때 해당 특성 정보에 얼마나 의존하는가?”라는 질문에 답한다. 학습에 사용하지 않은 Validation 데이터와 실제 목표 지표로 계산하면 일반화 상황의 의존도를 확인하는 데 더 적합하다.

### MDI와 순열 중요도 비교

| 구분 | MDI | 순열 중요도 |
| --- | --- | --- |
| 계산 시점 | 트리 학습 과정 | 학습이 끝난 뒤 |
| 주로 사용하는 데이터 | Train | Validation 또는 Test |
| 핵심 질문 | 이 특성의 분할이 불순도를 얼마나 줄였는가? | 이 특성 정보를 섞으면 평가 지표가 얼마나 떨어지는가? |
| 대표적인 함정 | 값의 종류가 많은 특성에 대한 편향 | 서로 강하게 연관된 특성이 중요도를 나누어 가짐 |
| 인과 효과 측정 | 아님 | 아님 |

예를 들어 `BM25_score`와 이를 정규화한 값이 거의 같은 정보를 담고 있다면 한 열을 섞어도 다른 열이 정보를 대신 제공할 수 있다. 이때 각 특성의 순열 중요도가 낮다고 해서 그 정보 자체가 불필요하다는 뜻은 아니다.

MDI는 높은데 순열 중요도가 낮다면 다음 가능성을 점검한다.

1. Train 데이터에서 우연히 좋은 분할에 자주 사용되었는가?
2. 값의 종류가 많아 MDI가 부풀려졌는가?
3. 과적합했는가?
4. Validation에서 상관된 다른 특성이 같은 정보를 대신하는가?
5. Train과 Validation의 분포나 데이터 생성 과정이 다른가?
6. 특성을 제거한 뒤 같은 Validation 기준에서 성능이 실제로 변하는가?

중요도 차이만 보고 곧바로 특성을 삭제하지 말고 원인을 조사한 뒤 제거 전후를 같은 조건에서 비교해야 한다.

## scikit-learn으로 직접 확인

### 기본 설정을 알고리즘으로 번역하기

```python
from sklearn.ensemble import RandomForestClassifier

forest = RandomForestClassifier(
    n_estimators=300,
    max_features="sqrt",
    oob_score=True,
    n_jobs=-1,
    random_state=42,
)
```

- `n_estimators=300`: 결정 트리를 300개 만든다.
- `max_features="sqrt"`: 각 노드의 분할마다 전체 특성 수의 제곱근 정도를 후보로 본다.
- `oob_score=True`: 각 행을 학습하지 않은 트리들로 OOB 예측과 점수를 계산한다.
- `n_jobs=-1`: 사용 가능한 CPU 코어를 활용해 트리 학습을 병렬화한다.
- `random_state=42`: 부트스트랩과 특성 선택의 난수 흐름을 재현할 수 있게 고정한다.

분류 예측에서는 각 트리의 클래스 확률을 평균하고, 평균 확률이 가장 큰 클래스를 최종 클래스로 선택한다.

### 부트스트랩 비율과 OOB 예측 확인

다음 코드는 트리마다 실제로 사용한 행 인덱스를 살펴 고유한 행과 OOB 행의 평균 비율을 계산한다.

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import average_precision_score

X, y = make_classification(
    n_samples=1000,
    n_features=10,
    n_informative=5,
    n_redundant=2,
    weights=[0.8, 0.2],
    random_state=42,
)

forest = RandomForestClassifier(
    n_estimators=300,
    max_features="sqrt",
    oob_score=True,
    n_jobs=-1,
    random_state=42,
)
forest.fit(X, y)

n_samples = len(X)
unique_ratios = []
oob_counts = np.zeros(n_samples, dtype=int)

for sample_indices in forest.estimators_samples_:
    in_bag_counts = np.bincount(sample_indices, minlength=n_samples)
    unique_ratios.append(np.count_nonzero(in_bag_counts) / n_samples)
    oob_counts += in_bag_counts == 0

print(f"mean unique ratio: {np.mean(unique_ratios):.4f}")
print(f"mean OOB ratio: {1 - np.mean(unique_ratios):.4f}")
print(f"mean OOB trees per row: {np.mean(oob_counts):.1f}")
print("OOB decision shape:", forest.oob_decision_function_.shape)
print(f"OOB accuracy: {forest.oob_score_:.4f}")
print(
    "OOB AP:",
    f"{average_precision_score(y, forest.oob_decision_function_[:, 1]):.4f}",
)
```

scikit-learn 1.9.0에서 실행한 결과는 다음과 같다.

```text
mean unique ratio: 0.6324
mean OOB ratio: 0.3676
mean OOB trees per row: 110.3
OOB decision shape: (1000, 2)
OOB accuracy: 0.9460
OOB AP: 0.9359
```

이 결과에서 확인할 수 있는 내용은 다음과 같다.

1. 트리 하나가 보는 고유한 행의 평균 비율 $0.6324$는 이론적 근사치 $0.632$와 가깝다.
2. OOB 행의 평균 비율 $0.3676$은 이론적 근사치 $0.368$과 가깝다.
3. 행 하나는 300개 트리 중 평균 110.3개에서 OOB였으며, 이론적 기댓값 약 110개와 가깝다.
4. 클래스가 두 개이므로 `oob_decision_function_`은 샘플 1,000개와 클래스 2개의 확률을 담은 $(1000, 2)$ shape이다.

## 헷갈리기 쉬운 부분

| 헷갈리기 쉬운 생각 | 정확한 이해 |
| --- | --- |
| Bootstrap과 Bagging은 같은 말이다 | Bootstrap은 표본을 만드는 방법이고, Bagging은 여러 표본의 모델 예측을 집계하는 전략이다 |
| 부트스트랩 표본의 길이가 $n$이면 고유한 행도 $n$개다 | 길이는 $n$이지만 중복 때문에 고유한 행은 평균적으로 약 $0.632n$개다 |
| B는 항상 OOB다 | B가 OOB인지는 트리마다 다르다 |
| 부트스트랩은 새로운 데이터를 생성한다 | 기존 행을 복원 추출하여 행별 등장 횟수를 바꾼다 |
| 랜덤 포레스트는 특성을 무작위로 하나 골라 바로 분할한다 | 무작위 후보군을 만든 뒤 그 안에서 가장 좋은 분할을 찾는다 |
| 특성 후보는 트리마다 한 번만 뽑는다 | 분할할 노드마다 다시 뽑는다 |
| `max_features`가 작을수록 항상 좋다 | 낮은 트리 상관과 개별 트리의 예측력 사이에 상충 관계가 있다 |
| 트리 수를 무한히 늘리면 분산이 0이 된다 | 상관된 트리들이 함께 흔들리는 $\rho\sigma^2$ 부분은 트리 수만으로 사라지지 않는다 |
| OOB는 완벽한 Validation이다 | 그룹·시간·문서 의존성이 있으면 별도의 목적 지향적 분할이 필요하다 |
| MDI가 높으면 인과적으로 중요한 특성이다 | MDI와 순열 중요도 모두 모델의 예측 의존도를 보는 도구이지 인과 효과를 측정하지 않는다 |

## 실제 활용과 RAG·LLM 연결

### RAG 관련성 분류

다음과 같은 구조화된 특성이 있다면 랜덤 포레스트로 빠른 관련성 분류 baseline을 만들 수 있다.

```text
retrieval_score
document_length
source_type
recency
query_length
```

여러 트리는 `retrieval_score + recency`, `source_type + document_length`처럼 서로 다른 조건 조합을 학습할 수 있다. 다만 실제 RAG에서는 BM25, Dense Retriever, Cross Encoder, LLM reranker 같은 다른 방법도 사용하므로 랜덤 포레스트가 항상 최종 모델이라는 뜻은 아니다.

특히 하나의 문서를 여러 청크로 나눈 데이터에서는 문서 단위 분할을 사용해야 새로운 문서에 대한 성능을 더 정직하게 측정할 수 있다.

### LLM 평가의 앙상블 사고방식

랜덤 포레스트가 Transformer 내부에 직접 사용된다는 뜻은 아니지만, 여러 평가자나 여러 샘플의 결과를 집계하는 LLM 평가에서도 비슷한 관점을 적용할 수 있다.

```text
Judge 1 ─┐
Judge 2 ─┼─→ 결과 집계
Judge 3 ─┘
```

각 평가자가 어느 정도 정확하면서 서로 다른 오류를 낼 때 집계의 이점이 커진다. 평가자들이 같은 편향 때문에 항상 함께 틀리면 수만 늘려도 효과가 제한된다.

### 1. 부트스트랩 표본과 배깅의 차이는 무엇인가?

<details>
<summary>모범 답안 보기</summary>

부트스트랩은 원본 데이터에서 행을 복원 추출해 하나의 학습 표본을 만드는 **샘플링 방법이다**. 같은 행이 여러 번 뽑히거나 어떤 행은 한 번도 뽑히지 않을 수 있다.

배깅은 여러 부트스트랩 표본에 각각 모델을 학습하고, 그 모델들의 예측을 평균하거나 투표로 모으는 **앙상블 전략이다**. 즉 부트스트랩은 배깅을 구성하는 한 단계이고, 둘은 같은 말이 아니다.

</details>

### 2. $(1-1/n)^n$은 OOB 비율과 어떻게 연결되는가?

<details>
<summary>모범 답안 보기</summary>

원본 행이 $n$개일 때 특정 행 A가 한 번의 추출에서 뽑히지 않을 확률은 $1-1/n$이다. 복원 추출을 $n$번 하는 동안 A가 한 번도 뽑히지 않을 확률은 다음과 같다.

$$
\left(1-\frac{1}{n}\right)^n
$$

$n$이 커지면 이 값은 $e^{-1}\approx 0.368$에 가까워진다. 한 번도 뽑히지 않은 행이 그 트리의 OOB 행이므로 OOB 비율은 약 $36.8\%$다. 반대로 최소 한 번 뽑힌 고유한 행의 비율은 약 $63.2\%$다.

</details>

### 3. 한 행의 OOB 예측에는 왜 일부 트리만 사용하는가?

<details>
<summary>모범 답안 보기</summary>

행 B의 OOB 예측은 B를 부트스트랩 학습 표본에 포함하지 않은 트리들로만 만들어야 한다. B를 학습한 트리의 예측까지 섞으면 모델이 이미 본 데이터로 자신을 평가하게 되어 OOB 평가의 의미가 사라진다.

각 트리의 부트스트랩 표본이 다르므로 B를 학습한 트리와 학습하지 않은 트리도 서로 다르다. 따라서 OOB는 행의 고정 속성이 아니라 행과 트리 사이의 관계다.

</details>

### 4. 랜덤 포레스트의 무작위성은 어느 두 위치에 들어가는가?

<details>
<summary>모범 답안 보기</summary>

첫째, 각 트리를 학습할 행을 부트스트랩으로 복원 추출한다. 이 과정은 트리마다 보는 데이터 경험을 다르게 만든다.

둘째, 트리의 각 노드에서 분할 후보로 사용할 특성 일부를 무작위로 다시 뽑는다. 그다음에는 뽑힌 후보 안에서 가장 좋은 분할을 찾는다.

```text
행의 무작위성     → 트리마다 다른 부트스트랩 표본
특성의 무작위성   → 노드마다 다른 특성 후보군
```

</details>

### 5. `max_features`가 작아지면 무엇이 달라질 수 있는가?

<details>
<summary>모범 답안 보기</summary>

각 노드가 볼 수 있는 특성 수가 줄어들면 강한 특성이 후보에서 빠질 가능성이 커진다. 그 결과 트리들이 서로 다른 분할을 선택하여 트리 사이의 오류 상관이 낮아질 수 있다는 점은 유리하다.

반면 좋은 특성을 사용하지 못해 각 트리의 분할 품질과 개별 예측력이 낮아질 수도 있다. 따라서 `max_features`는 단순히 작을수록 좋은 값이 아니라 **트리의 예측력과 트리 사이의 낮은 상관을 조절하는 값이다**.

</details>

### 6. 트리 수 $N$을 늘려도 왜 $\rho\sigma^2$는 사라지지 않는가?

<details>
<summary>모범 답안 보기</summary>

단순화한 평균 예측의 분산은 다음과 같다.

$$
\mathrm{Var}(\overline{T})
=
\rho\sigma^2
+
\frac{(1-\rho)\sigma^2}{N}
$$

트리마다 독립적으로 흔들리는 두 번째 항은 $N$으로 나누므로 트리 수가 늘어날수록 0에 가까워진다. 그러나 $\rho\sigma^2$는 트리들이 같은 방향으로 함께 흔들리는 부분이므로 $N$으로 나누어지지 않는다.

따라서 상관된 트리를 계속 추가하는 것만으로는 공통된 오류를 없앨 수 없다. 랜덤 포레스트가 특성 무작위성으로 트리 사이의 상관 $\rho$도 낮추려는 이유가 여기에 있다.

</details>

### 7. MDI와 순열 중요도는 각각 어떤 질문에 답하는가?

<details>
<summary>모범 답안 보기</summary>

MDI는 “트리를 학습할 때 이 특성을 사용한 분할들이 불순도를 얼마나 많이 줄였는가?”를 측정한다. Train 데이터와 트리 구조를 기반으로 하며, 값의 종류가 많은 특성의 중요도가 부풀려질 수 있다.

순열 중요도는 “학습이 끝난 모델에서 이 특성의 값을 섞어 정보를 깨뜨리면 평가 지표가 얼마나 떨어지는가?”를 측정한다. Validation 데이터에서 계산하면 일반화 상황의 예측 의존도를 볼 수 있지만, 서로 강하게 연관된 특성들이 같은 정보를 대신 제공하면 각 중요도가 낮게 나올 수 있다.

두 방법 모두 모델이 특성을 사용하는 방식을 설명할 뿐 인과 효과를 측정하지는 않는다.

</details>

## 한 문장 요약

랜덤 포레스트는 서로 다른 부트스트랩 표본과 노드별 특성 후보로 결정 트리들을 다양하게 만든 뒤 예측을 평균하여, 개별 트리의 예측력을 유지하면서 트리 사이의 오류 상관과 전체 분산을 낮추는 모델이다.
