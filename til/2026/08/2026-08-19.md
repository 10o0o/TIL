## 오늘의 학습

### 딥러닝이 학습하는 것

규칙 기반, 머신러닝, 딥러닝을 비교하면서 딥러닝의 핵심 차이를 정리했다. 딥러닝은 예측 규칙뿐 아니라 예측에 필요한 중간 표현도 여러 층에서 함께 학습한다. 중간층마다 별도의 정답을 주지 않아도 최종 loss를 기준으로 각 층의 parameter가 함께 학습된다.

아주 단순한 예로 `x`, `y`, `w`, `pred`의 shape가 모두 `(1, 1)`이고 다음과 같다고 가정했다.

```text
x = 2
y = 6
w = 1
learning_rate = 0.1
```

먼저 forward에서 현재 parameter로 예측값을 만든다.

```text
pred = x * w
     = 2 * 1
     = 2
```

정답은 `6`인데 `2`를 예측했으므로 MSE loss는 `16`이다.

```text
loss = (pred - y) ** 2
     = (2 - 6) ** 2
     = 16
```

backward에서는 parameter가 loss에 미치는 영향을 계산한다.

```text
dL/dw = 2 * (w*x - y) * x
      = 2 * (2 - 6) * 2
      = -16
```

gradient가 `-16`이라는 것은 현재 위치에서 `w`를 증가시키면 loss가 감소하는 방향이라는 뜻이다. SGD는 gradient의 반대 방향으로 parameter를 실제 변경한다.

```text
w_new = w - learning_rate * gradient
      = 1 - 0.1 * (-16)
      = 2.6
```

변경된 `w=2.6`으로 다시 계산하면 예측값은 `5.2`, loss는 `0.64`가 된다. 이 흐름을 PyTorch 코드로 대응하면 다음과 같다.

```python
optimizer.zero_grad()  # 이전 gradient 제거
pred = model(x)        # 현재 parameter로 예측
loss = loss_fn(pred, y)
loss.backward()        # gradient 계산 및 저장
optimizer.step()       # gradient를 사용해 parameter 변경
```

결정적인 구분은 `forward`는 현재 parameter로 예측하고, `backward`는 각 parameter의 gradient를 계산하며, `optimizer.step()`은 그 gradient를 이용해 parameter를 실제 변경한다는 점이다.

### 문제 유형에 따른 출력과 loss

동일한 입력 `X`를 사용하더라도 무엇을 예측하느냐에 따라 마지막 출력층, 정답 Tensor, loss가 달라진다.

```text
회귀
모델 출력: (B, 1), 실수
정답:      (B, 1), float
loss:      MSELoss

이진 분류
모델 출력: (B, 1), logit
정답:      (B, 1), float 0/1
loss:      BCEWithLogitsLoss

다중 클래스 분류
모델 출력: (B, C), 클래스별 logits
정답:      (B,), long class index
loss:      CrossEntropyLoss

다중 레이블 분류
모델 출력: (B, C), 레이블별 logits
정답:      (B, C), float 0/1
loss:      BCEWithLogitsLoss
```

logit은 확률로 바꾸기 전 모델이 출력한 원시 점수다. 음수이거나 `1`보다 클 수도 있다. 이진 분류를 학습할 때는 logit을 그대로 `BCEWithLogitsLoss`에 전달한다.

```python
loss = loss_fn(logits, y)
```

판정이 필요할 때만 sigmoid로 확률을 만든 뒤 기준값과 비교한다.

```python
probs = torch.sigmoid(logits)
pred_labels = (probs >= 0.5).long()
```

다중 클래스 분류에서 배송, 환불, 결제 중 하나를 고른다면 샘플마다 클래스별 점수가 필요하다.

```text
logits[0] = [배송 점수, 환불 점수, 결제 점수]
```

배치가 `2`이고 클래스가 `3`개라면 `logits.shape == (2, 3)`, `y.shape == (2,)`이다.

```python
y = torch.tensor([1, 2])
```

첫 번째 샘플의 정답은 class `1`, 두 번째 샘플의 정답은 class `2`다. `y`는 보통 one-hot vector가 아니라 class index이며 dtype은 `torch.long`이다. `CrossEntropyLoss`는 logits와 정답 클래스의 위치를 비교한다.

LLM의 다음 token 예측도 같은 구조로 볼 수 있다.

```text
logits.shape = (batch, sequence_length, vocabulary_size)
target.shape = (batch, sequence_length)
```

각 token 위치에서 전체 vocabulary 중 다음 token 하나를 고르는 거대한 다중 클래스 분류다.

다중 레이블에서는 하나의 샘플에 여러 레이블이 동시에 붙을 수 있다. 문의 하나가 환불 요청이면서 강한 불만일 수도 있다.

```python
# label 0: 환불
# label 1: 불만
# label 2: 개인정보 포함
y = torch.tensor([
    [1, 1, 0],  # 환불과 불만
    [0, 0, 1],  # 개인정보 포함
], dtype=torch.float32)
```

이 경우 `logits.shape == (2, 3)`, `y.shape == (2, 3)`이고 `BCEWithLogitsLoss`를 사용한다.

### 한 batch의 학습 및 평가 흐름

다음처럼 샘플 `200`개와 feature `4`개가 있다고 가정했다.

```python
X = torch.randn(200, 4)
y = torch.randn(200, 1)

train_loader = DataLoader(
    train_dataset,
    batch_size=32,
    shuffle=True,
)
```

batch는 총 `7`개이고 마지막 batch에는 샘플 `8`개가 들어간다. 일반적인 batch 하나를 꺼내면 다음 shape를 갖는다.

```text
batch_x.shape = (32, 4)
batch_y.shape = (32, 1)
```

모델은 다음과 같이 구성할 수 있다.

```python
model = nn.Sequential(
    nn.Linear(4, 16),
    nn.ReLU(),
    nn.Linear(16, 1),
)
```

한 batch가 통과하는 Shape 흐름은 다음과 같다.

```text
(32, 4)
→ Linear(4, 16)
→ (32, 16)
→ ReLU
→ (32, 16)
→ Linear(16, 1)
→ (32, 1)
```

`Linear`는 마지막 feature 축만 바꾼다. `ReLU`는 각 숫자를 독립적으로 변환하므로 Shape를 바꾸지 않는다.

`model.train()`은 학습 모드, `model.eval()`은 평가 모드를 설정한다. 대표적으로 Dropout과 BatchNorm의 동작이 달라진다.

- Dropout은 학습 모드에서 일부 값을 무작위로 끄고 평가 모드에서는 끄지 않는다.
- BatchNorm은 학습과 평가에서 평균과 분산을 사용하는 방식이 다르다.

Linear와 ReLU만 있는 현재 예제에서는 출력 차이가 없지만, 이후 복잡한 모델을 위해 모드를 명확히 설정한다. 중요한 점은 `model.train()` 자체가 parameter를 학습시키는 것은 아니라는 점이다.

`torch.no_grad()`는 연산 과정을 gradient 계산용 그래프로 기록할지를 제어한다. validation에서는 backward가 필요 없으므로 그래프를 만들지 않아 메모리와 계산을 줄일 수 있다.

```text
model.eval()
→ Dropout과 BatchNorm 등의 동작을 평가 방식으로 변경

torch.no_grad()
→ gradient 계산용 연산 기록을 중단
```

둘 중 한쪽이 다른 쪽을 대신하지 않는다.

```text
model.eval()만 사용
→ layer는 평가 모드지만 gradient 그래프는 기록될 수 있음

torch.no_grad()만 사용
→ gradient 그래프를 기록하지 않지만 layer는 기존 모드 그대로임

model.eval() + torch.no_grad()
→ 평가 동작과 gradient 기록 중단을 함께 적용
```

어느 경우든 `optimizer.step()`이 없다면 parameter가 자동으로 변경되지는 않는다.

### epoch loss, logging, checkpoint

`MSELoss()`의 기본 설정에서 `loss.item()`은 현재 batch의 평균 loss다. batch마다 샘플 수가 다를 수 있으므로 batch 평균을 단순 평균하면 안 된다.

```text
batch 1: 샘플 2개, 평균 loss 1
batch 2: 샘플 1개, 평균 loss 4
```

batch 평균끼리 단순 평균하면 `2.5`지만 샘플별 전체 평균은 다음과 같다.

```text
batch 1의 loss 합: 1 * 2 = 2
batch 2의 loss 합: 4 * 1 = 4
전체 loss 합: 6
전체 샘플 수: 3
epoch 평균 loss: 6 / 3 = 2
```

따라서 batch 크기를 다시 곱해 모든 loss의 합을 모은 뒤 전체 데이터 수로 나눈다.

```python
total_loss += loss.item() * batch_x.size(0)
epoch_loss = total_loss / len(dataloader.dataset)
```

`loss.item()`은 scalar Tensor의 값을 Python 숫자로 꺼내 logging에 사용한다. 실제 gradient 계산은 그전에 원래 loss Tensor로 수행한다.

```python
loss.backward()      # Tensor를 이용한 gradient 계산
value = loss.item()  # 기록할 Python 숫자 추출
```

epoch이 끝나면 train과 validation 결과를 기록할 수 있다.

```python
history.append({
    "epoch": epoch,
    "train_loss": train_loss,
    "valid_loss": valid_loss,
})
```

train loss와 validation loss가 함께 감소하면 학습과 일반화가 함께 개선되는 신호다. train loss는 감소하지만 validation loss가 증가하면 학습 데이터에는 맞지만 validation 성능은 나빠지는 과적합 신호다.

추론용 가중치는 다음처럼 저장할 수 있다.

```python
torch.save(model.state_dict(), "model.pt")
```

이 파일로 추론하려면 같은 모델 구조를 다시 만든 뒤 가중치를 불러온다. 중단된 학습을 그대로 재개하려면 일반적으로 다음과 같은 상태가 더 필요하다.

```text
model_state_dict
optimizer_state_dict
epoch
best_valid_loss
config
```

optimizer도 momentum 같은 내부 상태를 가질 수 있으므로 `model.state_dict()`만으로는 완전한 학습 상태가 아니다.

### Tensor의 Shape, dtype, device와 broadcasting

Tensor를 보면 값뿐 아니라 `shape`, `ndim`, `dtype`, `device`를 함께 읽는다.

Scalar와 빈 Tensor는 다르다.

```python
scalar = torch.tensor(7)
```

```text
값: 7
shape: ()
ndim: 0
numel: 1
dtype: torch.int64
```

`shape == ()`는 값이 없다는 뜻이 아니다. 축은 없지만 값 하나가 있는 0차원 Tensor다. 반면 다음은 길이가 `0`인 1차원 Tensor다.

```python
empty = torch.tensor([])
```

```text
shape: (0,)
ndim: 1
numel: 0
```

1차원 Tensor는 그 자체로 행이나 열 방향이 정해져 있지 않다.

dtype은 숫자를 해석하는 규칙이다. `torch.tensor()`는 입력 데이터로부터 dtype을 추론한다. 정수 목록은 보통 `torch.int64`, 실수 목록은 기본 실수 dtype을 적용한다. 기본 실수 dtype은 보통 `torch.float32`이지만 `torch.set_default_dtype()`로 변경할 수 있다. 중요한 Tensor는 dtype을 명시하는 편이 안전하다.

기본 설정에서 `nn.Linear`의 weight는 `torch.float32`다. 입력 Tensor의 dtype이 다르면 바로 넣을 수 없으므로 맞춰야 한다.

```python
sample = torch.tensor([1.0, 2.0, 3.0, 4.0])

a = sample.unsqueeze(0)  # (4,) → (1, 4)
b = sample.unsqueeze(1)  # (4,) → (4, 1)
```

`unsqueeze(dim)`은 지정한 위치에 크기가 `1`인 축을 하나 추가한다. `squeeze`는 반대로 크기가 `1`인 축을 제거한다.

`device`는 Tensor의 숫자가 CPU 메모리에 있는지 GPU 메모리에 있는지를 나타낸다. 모델과 입력 Tensor가 서로 다른 device에 있으면 연산할 수 없다.

Broadcasting은 다음 규칙으로 Shape을 비교한다.

```text
오른쪽 축부터 비교한다.
크기가 같으면 호환된다.
둘 중 하나가 1이면 호환된다.
둘 다 다르고 어느 것도 1이 아니면 오류가 발생한다.
```

## 배운 점

- 딥러닝에서는 최종 예측뿐 아니라 예측에 유용한 중간 특징 표현도 함께 학습하며, 중간층에 별도의 정답이 필요하지 않다는 점을 이해했다.
- `backward()` 직후에는 parameter가 바뀌지 않고 gradient만 저장되며, 실제 parameter 변경은 `optimizer.step()`에서 일어난다는 구분이 중요했다.
- `model.eval()`과 `torch.no_grad()`는 서로 다른 역할을 하므로 validation에서는 보통 둘을 함께 사용한다.
- 문제 유형에 따라 logits와 target의 Shape 및 dtype 계약이 달라진다는 점을 알게 됐다.
- Tensor를 볼 때 값만 보지 않고 먼저 `shape`, `dtype`, `device`를 확인하는 습관이 중요하다.
- `shape == ()`인 scalar Tensor와 값이 없는 Tensor는 다르며, 1차원 Tensor는 아직 행이나 열 방향이 정해지지 않았다는 점을 정리했다.
- Broadcasting은 편리하지만 `(B, 1)`과 `(B,)`처럼 의도치 않게 더 큰 Shape을 만들 수 있으므로 오른쪽 축부터 확인해야 한다.
